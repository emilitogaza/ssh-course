# Your First Connection

Enough theory — let's log in. This chapter connects you to a server, narrates
exactly what you see, and shows you around the remote shell. If you have a server
to practise on (a cheap VPS, a Raspberry Pi, even another computer on your
network), follow along. If not, read it through — it'll be second nature by the
time you have one.

## The command

```bash
ssh deploy@example.com
```

Dissected one more time, because now every piece has meaning:

- **`ssh`** — the client on your machine.
- **`deploy`** — the **user account** on the server you're logging in as.
- **`@`** — separator.
- **`example.com`** — the **host** (a name DNS resolves, or a raw IP like
  `203.0.113.10`).

If SSH runs on a non-standard port, add `-p`:

```bash
ssh -p 2222 deploy@example.com
```

## What you'll see, in order

**First connection to this server** — the host-key prompt from the last chapter:

```text
The authenticity of host 'example.com (203.0.113.10)' can't be established.
ED25519 key fingerprint is SHA256:Ux2Cq0m7…s9plQ.
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
```

Type `yes`. (This won't appear again for this server.)

**Authentication** — one of:

- With keys set up and an agent loaded: *nothing to do* — you're logged straight
  in.
- With a passphrase not yet cached: a prompt for your **key passphrase** (local —
  it unlocks your private key).
- With password auth: a prompt for the **account password** on the server.

> **Passphrase vs password — the perennial mix-up.** A *passphrase* prompt unlocks
> **your private key on your machine**. A *password* prompt sends the **server
> account's password** to the server. Same-looking prompt, completely different
> secret. If you set up keys and still get asked for the *server* password, key
> auth didn't take — jump to the errors chapter.

**You're in** — the prompt changes to the server's:

```text
deploy@web-01:~$
```

That prompt is generated by the **server**. `deploy` is who you are, `web-01` is
the server's hostname, `~` is your current directory (your home). You're now typing
into the remote machine.

## Prove you're really "there"

A couple of harmless commands to feel the remoteness:

```bash
hostname     # prints the SERVER's name, not your laptop's
whoami       # prints 'deploy' — who you're logged in as there
pwd          # /home/deploy — your home on the server
ls -la       # the server's files
uptime       # how long the server has been running
```

Everything reports the **server's** reality. Your laptop is just the keyboard and
screen; the computer is elsewhere.

## Running one command without "staying"

You don't have to open an interactive session. Tack a command onto the end and SSH
runs just that, prints the output, and exits — great for scripts and quick checks:

```bash
ssh deploy@example.com "df -h"      # disk space on the server, then back to your shell
ssh deploy@example.com "uptime"
```

You never get the remote prompt; you get the output and you're back on your own
machine. This is the seed of a lot of automation.

## Logging out

To end an interactive session, any of:

```bash
exit
```

…or type `logout`, or press **Ctrl-D**. The shell ends, the tunnel closes, and your
prompt returns to your laptop's. If a session ever seems frozen (network dropped),
the escape sequence **`~.`** (tilde then dot, at the start of a line) force-closes
it.

## What just happened, in terms you now own

Threading it back through the whole course:

1. Client resolved `example.com` → an **IP**, connected on **port 22**.
2. Handshake built the **encrypted tunnel** (asymmetric to agree a key, then
   symmetric for the session).
3. The server presented its **host key**; you trusted it (saved to
   `known_hosts`).
4. You authenticated — your client **signed a challenge** with your **private
   key**, verified against your **public key** in the server's `authorized_keys`.
5. The server started a **shell**; its prompt is what you're typing into.

Every mysterious step from chapter one is now a thing you can name. Next: how to
get your key onto a server that's never heard of you — turning that first
password-or-provisioned login into permanent, password-free access.

> **Key takeaways**
>
> - Connect with **`ssh user@host`** (add **`-p`** for a non-standard port).
> - First time, you'll answer the **host-key prompt**; after that it's silent.
> - A **passphrase** prompt unlocks your **local key**; a **password** prompt is
>   the **server account's** — don't confuse them.
> - Append a command (`ssh user@host "df -h"`) to run it and exit; **`exit`** or
>   **Ctrl-D** ends a session.
